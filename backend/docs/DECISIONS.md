## ✅ 问题1：主脑选择和用户权限系统

### 决策1.1：主脑选择

**决策：** 使用 `master_brain.py`

**原因：**
- ✅ 支持动态权限检查（不同用户不同功能）
- ✅ 支持小程序类型识别
- ✅ 意图识别更智能（LLM分析）
- ✅ 扩展性强
- ✅ 适合多用户、多小程序、多技能的复杂场景

---

### 决策1.2：用户身份系统

**决策：** 三态权限系统

| 用户状态 | 定义 | 可用功能 |
|---------|------|---------|
| **纯个人用户** | 没有企业归属 | ✅ 宁律师家族（咨询、起草）<br>✅ 合同场景师（起草）<br>✅ 理约（签署）<br>❌ 防风险（不能登录） |
| **企业成员（未认证）** | 有企业归属，但企业未认证 | ✅ 宁律师家族（咨询、起草）<br>⚠️ 防风险（可登录，功能受限）<br>✅ 合同场景师（起草）<br>✅ 理约（签署）<br>⚠️ 功能受限：只能起草合同，不能做合规检查 |
| **企业成员（已认证）** | 有企业归属，企业已认证 | ✅ 宁律师家族（咨询、起草）<br>✅ 防风险（全部功能）<br>✅ 合同场景师（起草）<br>✅ 理约（签署）<br>✅ 码上签约（电子签名） |

---

### 决策1.3：小程序和技能

| 小程序 | 独有技能 | 共享技能 | 可用用户 |
|-------|---------|---------|---------|
| **宁律师家族** | 刑事咨询、民事咨询、劳动咨询 | 起草合同、签署合同 | 个人、企业成员 |
| **防风险** | 企业合规、风险评估 | 起草合同、签署合同 | 企业成员（未认证受限） |
| **合同场景师** | - | 起草合同、合同审查 | 个人、企业成员 |
| **理约** | - | 合同提醒、签署合同 | 个人、企业成员 |
| **码上签约** | - | 电子签名、签署合同 | 个人、企业成员 |

## ✅ 问题3：开发框架和技术栈

### 决策3.1：项目背景（重要！）

**背景：**
- 第一版项目使用**扣子平台的智能体开发框架**
- 现在第二版：用 **LangGraph** 模仿扣子智能体的工作方式

**架构演变：**
```
第一版（旧）：
扣子平台智能体开发框架

第二版（现在）：
LangGraph（模仿扣子智能体的工作方式）
```

---

### 决策3.2：智能体开发方式

| 智能体类型 | 开发方式 | 使用框架 |
|----------|---------|---------|
| **简单智能体** | 自己开发 | LangChain |
| **复杂智能体** | 自己开发（模仿扣子） | LangGraph |
| **业务功能复杂的** | 使用MCP服务 | LangGraph + MCP |

**开发原则：**
- ✅ 效果和体验优先
- ✅ 成本考虑（保证效果前提下选择低成本方案）

---

### 决策3.3：MCP服务使用

**使用场景：**
- ✅ 业务功能复杂的 → 尽量采用MCP服务
- ✅ 简单的 → 自己开发

**MCP服务类型：**
| MCP类型 | 说明 |
|-------|------|
| **开源MCP服务器** | 使用开源的MCP服务（文件系统、数据库、Git等） |
| **开源Skill** | 使用开源的技能（GitHub上的开源技能） |
| **自定义MCP服务器** | 自己开发MCP服务（企业内部系统） |

## 🏗️ 最终架构（完整版）

```
用户请求（微信小程序 / PC端）
  ↓
Master Brain（用LangGraph实现，模仿扣子的路由）
  ├─ 意图识别（LLM分析）
  ├─ 权限检查（用户身份 + 小程序类型）
  └─ 路由到对应技能
  ↓
技能层（Skills）
  ├─ 简单技能 → 自己开发（LangChain）
  │  ├─ 刑事咨询
  │  ├─ 民事咨询
  │  └─ 合同起草
  │
  └─ 复杂技能 → 用LangGraph开发
     ├─ 企业合规检查
     └─ 风险评估
     ↓
  工具层（Tools）
     ├─ 简单工具 → 自己开发
     │  ├─ 知识库检索
     │  └─ 文件处理
     │
     └─ 复杂工具 → MCP服务
        ├─ 开源MCP（文件系统、数据库）
        └─ 自定义MCP（企业内部系统）

底层服务：
├─ 扣子知识库API（必须使用）
├─ 大模型（扣子、DeepSeek、智谱、腾讯，用LangChain封装）
├─ 扣子智能体API（按需使用，复杂智能体用）
└─ 数据库（PostgreSQL + Redis）
```
