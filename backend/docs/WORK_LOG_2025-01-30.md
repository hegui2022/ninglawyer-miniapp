## 📋 工作概述

根据项目决策文档`backend/docs/DECISIONS.md`，完成了宁律师项目第一版后端API的开发。第一版采用MVP策略，全部智能体使用扣子官方API实现，优先考虑成本。

---

## 🎯 核心决策

### 第一版策略

1. **尽量少功能** - MVP（最小可行性产品）
2. **全部智能体用扣子API实现** - 节省开发时间
3. **优先级：成本 > 体验 > 效果**
4. **责任分工**：
   - 用户负责：主脑、小程序前后端、后台PC端管理功能
   - AI负责：后端全部问题（API、数据库、扣子集成等）

### 技术架构

```
用户请求（微信小程序 / PC管理端）
  ↓
前端（用户负责）
  ↓
后端API（AI负责）
  ├─ /api/consultation/*  咨询接口
  ├─ /api/contract/*      合同接口
  ├─ /api/auth/*          认证接口
  └─ /api/admin/*         管理接口（预留）
  ↓
扣子智能体API（全部智能体都用这个）
```

#### API接口

| 接口 | 方法 | 功能 | 认证 |
|------|------|------|------|
| /api/auth/wechat/login | POST | 微信登录 | 否 |
| /api/auth/verification-code/send | POST | 发送验证码 | 否 |
| /api/auth/verification-code/verify | POST | 验证验证码 | 否 |
| /api/auth/bind-phone | POST | 绑定手机号 | 是 |
| /api/auth/user-info | GET | 获取用户信息 | 是 |

#### 核心实现

**微信登录流程**:
```
1. 接收微信code
2. 调用微信API获取openid和unionid
3. 查找或创建用户
4. 生成JWT token
5. 返回token和用户信息
```

**验证码流程**:
```
1. 生成6位数字验证码
2. 保存到Redis（5分钟过期）
3. 发送短信（第一版使用日志模拟）
```

- ✅ 微信登录接口实现
